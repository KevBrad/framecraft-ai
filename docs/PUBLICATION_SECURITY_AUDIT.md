No exposed credential was identified in the inspected publication candidates. No credential rotation recommendation follows from this review. ## Publication strategy

Create a new intentional history from the sanitized source package, not from the private working directory. Do not add the original repository wholesale. Do not force-push over unrelated history. Retain the original local application and its data unchanged.

The public `.gitignore` excludes local configuration, OAuth client files, token files, databases, user media, model weights, downloaded executables, environments, generated tests, logs and build output. Ignore rules are a secondary guard. The primary protection is the explicit publication allowlist plus final content scanning.

No application source license has been selected. Do not create an MIT, Apache or other grant for the user's source. The maintainer's source-availability notice must distinguish application code from the third-party font, dependency and test-fixture licenses.

## Reproducible checks

The exact proposed lightweight Windows CI command executed on the sanitized source package:

```powershell
python -m pytest -q backend/test_pipeline.py::HighlightTests backend/test_resources.py::DiskBudgetTests tests/test_chunked_transcription.py tests/test_drive.py tests/test_ingestion.py tests/test_import_transport.py tests/test_director.py tests/test_editorial.py -k "not real_decoded_motion_fixture and not retained_legacy_style_can_render_independent_opening_hook"
```

Result: **177 passed, 2 deselected in 11.42 seconds**. The two explicitly deselected tests require generated media. This command downloads no speech model and uses no private media or live Google credentials. Dependencies are the existing application requirements.

The standard CI separates the frontend production build from Windows logic, transport and secret-storage tests. An explicit manual media workflow prepares the official public-domain JFK speech fixture and a checksum-pinned NASA photo with clearly synthetic motion before running the full suite. All generated fixtures remain ignored. GitHub Actions use immutable revisions of the official checkout, setup-python and setup-node actions, looked up from their documented v7 tags. No repository secret is required.

## Packaging-only changes

- Windows setup now discovers the installed Python launcher or interpreter rather than assuming a Codex-specific runtime path. It creates a conventional virtual environment with pip.
- A public fixture-preparation helper makes the motion fixture before the full suite, removing reliance on artifacts generated by a previous local test run.
- Publication ignore rules and the two CI workflows are new. Application algorithms remain unchanged.

## Initial review boundary

The initial code/packaging review covered source only. The final payload review below supersedes that limited boundary. Proposed Git history and remote publication remain separate gates owned by the publishing workflow.

## Final public-payload gate

**Pass, before the first publication commit.** The final source/document payload contains 113 files, approximately 10.1 MB. The separately prepared profile contains one README. Review results:

- Gitleaks 8.30.1 redacted directory scans reported zero findings for the complete public-source directory, profile README, and extracted PDF/presentation text, notes, relationships and metadata.
- A path/type allowlist found no user data directory, database, credential, model weight, environment, downloaded executable, private log, unrelated project or symlink in the payload.
- All 36 backend/frontend application-source files match the initial SHA-256 manifest. The portfolio work has not changed the application's algorithms.
- All nine approved product assets match the reviewed asset manifest. The only audiovisual publication asset is the explicitly approved, muted 37.8-second H.264 preview at 1080 x 1920. Independent ffprobe inspection confirms zero audio streams. Its original graphics and actual public-domain speech processing, manual caption refinements and upscaling disclosure are documented in the asset provenance.
- The inspected dashboard, editor and output screenshots show the isolated public demonstration workspace and original graphics, with no private user project, machine path or credential visible. The parent presentation workflow reviewed the complete slide and document layouts.
- The PowerPoint contains 12 slides with native editable text on every slide, 12 notes parts and three embedded images. XML/relationship inspection found no private host path, macro, embedded OLE payload or non-web external relationship.
- The pitch PDF contains 12 image-based pages, the case study six searchable-text pages, and the overview one searchable-text page. They are unencrypted. Text and metadata contain no private host path. No embedded attachment, launch or JavaScript action was found. Public links use HTTP(S). The image-based pitch PDF limitation is explicitly documented beside its editable PowerPoint source.

This gate approves the prepared **file payload** for the parent's intentional first commit. It does not assert that proposed Git objects or history have been scanned, that a public push has occurred, or that GitHub rendering/downloads have been verified. The parent must inspect the exact staged list and scan the new source/profile histories before any push, then verify the published repositories separately. Scanner results reduce exposure risk but do not prove the absence of every possible secret or a production security boundary.
